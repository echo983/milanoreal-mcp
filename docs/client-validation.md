## 基础工具与项目文件

刷新工具列表后，在两端分别执行：

1. `container_ping`，核对普通用户、工作目录与运行时。
2. `container_exec` 执行 `pwd; id; node --version`，核对实际身份和退出码。
3. `container_files_list` 无参数调用，检查返回的 `path`、条目、URI 及 `truncated`，不要把本地 URI 当公网下载链接。
4. 在独立测试目录内，用文件工具写入含中文的小文件，再读取比对，随后删除并用 `test -e` 核对不存在。删除文件不会自动删除空父目录；只在确认它是本轮测试目录且为空时用 `rmdir` 清理。

每个工具只确认自己实际收到的结果；Shell 的 `ls` 不能替代 `container_files_list` 调用。大文件、并发和超时边界已由自动化覆盖，不必在真实项目上重复破坏性测试。

## 重连与服务重启

在测试目录写入标记并关闭当前对话，重新连接/新对话后读取。再由管理员安排重启 `milanoreal-mcp`，待健康检查就绪后，两端在不更换口令、不撤销授权的情况下分别调用 ping 并读取标记。记录是否需要重新授权，完成后清理标记。

重启会清理应用 cgroup 内的任务，先安排正在运行的作业；不为验证文件持久化而误停真实任务。现有 VPS 已证明普通文件跨真实服务重启保留；此处补的是客户端行为。

## 刷新

Access token 最长 1 小时。两端正常使用时，在原 access token 有效期结束后再次调用 ping，记录能否由客户端正常续接；无需向模型展示令牌，也不要为了加快验收去修改正式有效期或数据库。90 天连接期限是绝对期限，刷新不延长。

若客户端要求重新登录，记录时间和脱敏错误类别，区分到期、撤销、重放和网络问题，不用原始 token 辅助聊天诊断。本地测试已覆盖刷新轮换、到期和重放，并不意味着两端真实客户端均已完成这项验收。

## 撤销和重新登录

该步骤会同时影响两端连接，安排在可重新登录时进行。管理员按 [运维说明](operations.md) 执行 `revoke-all` 并输入 `REVOKE`；然后两端分别发起新工具调用，确认旧授权不能继续使用，再通过现有口令重新授权，验证 ping。已经运行的系统命令不会因撤销自动终止。

不为验证更换口令而要求用户发送口令。换口令对旧事务、授权码及 token 的影响已经由独立进程自动化测试覆盖。

## 等待时间

选择空闲时段，在两端各执行无副作用的 `sleep 50; printf 'wait-test complete\n'`，`timeout` 设为 60000 毫秒，记录是否收到完整结果与实际等待时间。如果客户端先断开，不把它记为命令未执行；此测试无副作用，但真实安装/写入命令不能照此盲目重试。

服务预算为默认 60 秒、最大 90 秒，不保证客户端或代理等待同样长。只有实测证明预算不适用时才调整常量；长任务使用后台日志，不以持续加长同步等待替代。
