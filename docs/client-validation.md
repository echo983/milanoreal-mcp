## 基础工具与项目文件

刷新工具列表后，在两端分别执行：

1. `container_ping`，核对普通用户、工作目录与运行时。
2. `container_exec` 执行 `pwd; id; node --version`，核对实际身份和退出码。
3. `container_files_list` 无参数调用，检查返回的 `path`、条目、URI 及 `truncated`，不要把本地 URI 当公网下载链接。
4. 在独立测试目录内，用文件工具写入含中文的小文件，再读取比对，随后删除并用 `test -e` 核对不存在。删除文件不会自动删除空父目录；只在确认它是本轮测试目录且为空时用 `rmdir` 清理。

每个工具只确认自己实际收到的结果；Shell 的 `ls` 不能替代 `container_files_list` 调用。大文件、并发和超时边界已由自动化覆盖，不必在真实项目上重复破坏性测试。

## 重连与服务重启

两端已在正式服务重启后通过现有连接调用 ping，均无需重新登录。若要单独验证跨对话的项目文件持续性，可在测试目录写入标记，关闭当前对话，在新对话读取并清理标记。

重启会清理应用 cgroup 内的任务，先安排正在运行的作业；不为验证文件持久化而误停真实任务。现有 VPS 已证明普通文件跨真实服务重启保留。

## 刷新

Access token 最长 1 小时。两端均已在原 access token 到期后通过现有连接调用 ping；服务端各记录一次 refresh 轮换和新 access token 签发。无需向模型展示令牌，也不要修改正式有效期或数据库。90 天连接期限是绝对期限，刷新不延长。

以后若客户端要求重新登录，记录时间和脱敏错误类别，区分到期、撤销、重放和网络问题，不用原始 token 辅助聊天诊断。

## 撤销和重新登录

该步骤会同时影响两端连接，安排在可重新登录时进行。管理员按 [运维说明](operations.md) 执行 `revoke-all` 并输入 `REVOKE`；然后两端分别发起新工具调用，确认旧授权不能继续使用，再通过现有口令重新授权，验证 ping。已经运行的系统命令不会因撤销自动终止。

不为验证更换口令而要求用户发送口令。换口令对旧事务、授权码及 token 的影响已经由独立进程自动化测试覆盖。

## 等待时间

现有结果：ChatGPT 的 50 秒调用成功；Claude 的 10 秒、30 秒调用成功，一次 50 秒调用在返回结果前遇到连接器错误。无需重复运行延时探针。如果日后重现断开，记录客户端发起与报错时间；连接断开不能证明命令未执行，真实安装或写入命令不要盲目重试。

服务预算为默认 60 秒、最大 90 秒，不保证客户端或代理等待同样长。只有实测证明预算不适用时才调整常量；长任务使用后台日志，不以持续加长同步等待替代。

## 50 秒调用差异的后续定位

两端列表调用已通过。ChatGPT 收到 50 秒命令的完整结果；Claude 报连接器错误，不能从这个错误确认命令没有执行，也不能据此认定其固定等待上限短于 50 秒。当前保持默认 60 秒、最大 90 秒不变。

[Claude 官方服务器接入文档](https://claude.com/docs/connectors/building) 标注 claude.ai/Desktop 单次工具调用超时为 240 秒；该文档值不是本次具体链路成功的保证，也没有证明故障发生在哪一层。用户随后确认独立的 10 秒、30 秒调用均成功，服务端耗时分别为 10012 ms、30007 ms，但没有客户端墙钟计时。一次 50 秒错误与这两次成功不能构成稳定阈值；不继续以二分法将其当作确定上限。后续若定位该故障，应记录请求发起/错误时间，并判断同条件下是否可复现；不自动重试失败调用。需要确认请求断开后的任务状态时，让新的诊断任务在自己独立的临时目录写开始与结束标记，再用短调用读取。

长任务仍使用 `setsid`、关闭 stdin 并重定向 stdout/stderr；不采用仅 `nohup ... &` 就已完全脱离的假设。此次不增加工具、不切换 SSE、不添加心跳或更改正式授权状态。
